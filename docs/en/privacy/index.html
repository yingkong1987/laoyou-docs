Development build notice

Privacy

This notice covers the current development build of 一桌老友 and this site. Developer Qin Yao now provides in-app intake for manually processing EOS guest-identity deletion. Processing times and receipts are explained below.

Updated and effective: 6 November 2026.

Scope and publisher

This notice covers 一桌老友 and this project documentation site. The developer and individual publisher is Qin Yao. The public support and privacy email is support@stackpaste.cn. GitHub account yingkong1987 maintains the project.

Offline practice and device storage

Computer opponents for all 20 available games run on the device without requiring an online identity. Apple keeps one Sichuan Blood Battle practice save and one shared save for the other games; starting a new practice of the corresponding type replaces its old save. Android keeps one save per game. Finished practice saves are cleared; a separate local summary may retain public scores from completed games. Private saves contain the hand and game state needed to resume, are excluded from automatic cloud backup and do not sync across devices. Preferences such as display name, settings and computer difficulty also stay on the device.

Cross-platform tables and guest identity

A cross-platform friend table uses Epic Online Services (EOS) to create and retain a device-associated guest identity. EOS processes information needed for sign-in, room membership, connections and transport. The SDK separately stores local identity credentials and runtime cache. The absence of an email or phone-number registration form does not mean there is no service identity.

Table and game data

Nicknames, online identifiers, room membership, ready status, round identifiers, actions, public game information and scores are shared with the provider and players as needed for the table. The host device stores and adjudicates the full game; other normal clients receive their own hand and public information. Share room codes only with intended players and avoid sensitive personal information in nicknames.

Original-table recovery

To return to a table you have not left, the app stores its original room, identity, fixed roster and seats, game and recovery state locally. The host checkpoint includes the full hands, wall or board history; other players save only their permitted view. Temporary interruptions do not deliberately erase this record; explicitly leaving clears it. Lost device data, missing original players or valid host state, or an unavailable original room may prevent recovery.

Apple-only tables

The Apple friend-table option for Sichuan Blood Battle uses Game Center identity, matching, invitations and communication. It requires the appropriate system, service and signing configuration. Apple handles related information under its service policies. Game Center and EOS cannot be mixed in one table. Apple-only tables do not offer the same cold-start recovery assurance as EOS.

Providers and diagnostics

The official EOS iOS SDK privacy manifest declares general categories including player identifiers, gameplay content, product interaction, performance, name and email, with some analytics purposes. The app adds no separate advertising or analytics SDK and does not offer email sign-in. Actual collection, retention, processing regions and App Store privacy labels for enabled SDK features still require verification. Limited local connection diagnostics can be explicitly enabled in a dedicated Debug copy; Release excludes that diagnostic writer and has no automatic upload of those records.

Clipboard and permissions

The app reads a room code from the clipboard only when you actively paste it. Copying and sharing are also your actions. The app currently has no recording, camera or contacts-import feature and requests no microphone, camera or contacts permission. Internet and local-network access support multiplayer.

Identity deletion and request status

About & Privacy provides EOS guest-identity deletion requests and progress. Manual intake is active in connected builds, and the process starts in the app without requiring a separate support email. Older development builds without the endpoint need an updated connected build. Explicitly leave any current or recoverable friend table first; offline play remains available during processing. Acceptance is not completion. A completed status must reflect actual provider deletion of the identity and related data. Leaving, uninstalling, clearing cache or posting publicly does not confirm server-side deletion.

Deletion-service data and retention

The intake and receipt service uses Cloudflare Workers/D1. Qin Yao checks each target’s scope before following the provider-supported deletion process. A short-lived identity token is used only for verification. The service stores an encrypted identity target, identity and receipt verification values, request ID, timestamps and status; it does not retain tokens, plaintext receipt secrets, nicknames or complete game states. Qin Yao has confirmed that he will personally handle in-app deletion requests, complete them within 30 days of formal acceptance, and retain the completed receipt for 30 days after deletion is confirmed. Unfinished requests are not cleared or marked deleted merely because time has passed. Completion is confirmed from the provider’s actual result and is available through the in-app receipt. The service uses Cloudflare hosting; D1 processing has been observed in WNAM and may involve cross-border processing. Provider platform logs and backups follow their own policies; the 30-day completed-receipt period does not describe those records.

Support and privacy requests

Contact support@stackpaste.cn for support or privacy assistance. Ordinary issues may also use public GitHub Issues. Begin with the app name, platform, version and problem; do not send access tokens, client secrets, receipt secrets or complete diagnostic logs, or post identity identifiers and room codes publicly. Support email assists users; it does not replace the in-app deletion process or actual completion receipt.

This site and updates

This is a static GitHub Pages site with no forms, ads, analytics scripts or third-party fonts. GitHub may process site-access records under its privacy statement. Deletion requests are handled by Cloudflare and the controlled operator process, not by this static site. We update this notice and its date when functionality or actual processing changes.
